## ۱. معرفی پروژه

### ۱.۱ عنوان و معرفی بازی دوز

عنوان پروژه «عامل هوشمند بازی دوز (Tic-Tac-Toe)» است. دوز بازی دونفره‌ای روی صفحه ۳×۳ (۹ خانه) است. دو بازیکن با نمادهای X و O به‌نوبت یک خانه خالی را انتخاب می‌کنند. بازیکنی که زودتر سه نماد یکسان را در یک سطر، ستون یا قطر قرار دهد برنده است و اگر صفحه پر شود و برنده‌ای وجود نداشته باشد، بازی مساوی است.

### ۱.۲ مسئله اصلی و اهداف

**مسئله اصلی:** طراحی عاملی که وضعیت صفحه را دریافت کند، حرکت‌های مجاز را تشخیص دهد و حرکتی برای بردن یا جلوگیری از باخت انتخاب کند (مطابق «مشخصات فنی»).

**اهداف کلی** (مطابق مشخصات فنی و README):

- مدل‌سازی دقیق محیط بازی پیش از ساخت عامل (README)
- مدیریت وضعیت، حرکت‌های مجاز و شرایط پایانی (برد، باخت، مساوی)

**اهداف جزئی:**

- تشخیص وضعیت صفحه، خانه‌های خالی و حرکت‌های مجاز
- انتخاب حرکت معتبر
- تلاش برای برد و جلوگیری از برد حریف
- تشخیص پایان بازی

### ۱.۳ محدوده پروژه (بر اساس شواهد)

## ۲. تعریف مسئله

### ۲.۱ شرح مسئله

باید محیطی استاندارد برای بازی دوز مدل‌سازی شود که وضعیت صفحه را نگه دارد، حرکت‌ها را اعتبارسنجی و اعمال کند و پایان بازی را تشخیص دهد؛ سپس عاملی روی این محیط بازی کند. در وضعیت فعلی فقط بخش «محیط» پیاده‌سازی و آزمون شده است.

### ۲.۲ ورودی‌ها و خروجی‌ها

**در سطح عامل (مطابق مشخصات فنی):**

| نوع | شرح |
|---|---|
| ورودی | وضعیت صفحه ۳×۳، نماد عامل، نماد حریف، نوبت فعلی، حرکت‌های مجاز |
| خروجی | انتخاب یک خانه خالی و مجاز؛ در پایان بازی، وضعیت نهایی |

**در سطح کد محیط (پیاده‌سازی واقعی):**

| نوع | شرح |
|---|---|
| ورودی `step(action)` | عدد صحیح ۰ تا ۸ (شاخص خانه) |
| خروجی `step` | چهارتایی `(board_copy, winner, done, info)` که `info` همیشه دیکشنری خالی `{}` است |
| خروجی `reset()` | کپی آرایه صفحه اولیه |
| خروجی `get_legal_actions()` | فهرست شاخص خانه‌های خالی (یا فهرست خالی پس از پایان بازی) |

### ۲.۳ قوانین بازی

مطابق مشخصات فنی: صفحه ۹ خانه؛ حرکت نوبتی؛ انتخاب خانه پر مجاز نیست؛ سه نماد یکسان در سطر، ستون یا قطر برد است؛ پر شدن صفحه بدون برنده مساوی است؛ پس از پایان بازی حرکت جدید مجاز نیست. هر هفت قانون در کد محیط تحقق یافته‌اند (جزئیات در بخش ۵).

### ۲.۴ شرایط برد، باخت و مساوی

هشت خط برد در کد تعریف شده است (ثابت `WIN_LINES`):

| نوع | خانه‌ها |
|---|---|
| سطرها | (۰،۱،۲)، (۳،۴،۵)، (۶،۷،۸) |
| ستون‌ها | (۰،۳،۶)، (۱،۴،۷)، (۲،۵،۸) |
| قطرها | (۰،۴،۸)، (۲،۴،۶) |

مقدار متغیر `winner`:

| مقدار | مفهوم |
|---|---|
| `None` | بازی ادامه دارد |
| `1` | X برنده شد |
| `-1` | O برنده شد |
| `0` | مساوی |

### ۲.۴.۱ نمایش صفحه و شماره‌گذاری خانه‌ها

صفحه به‌صورت آرایه یک‌بعدی NumPy با ۹ عنصر ذخیره می‌شود. شماره‌گذاری سطری (row-major) است:

```
 0 | 1 | 2
---+---+---
 3 | 4 | 5
---+---+---
 6 | 7 | 8
```

کدگذاری مقادیر: `1` = X، `-1` = O، `0` = خانه خالی. تابع `render()` خانه خالی را با «`.`» نشان می‌دهد.

### ۲.۵ مدیریت نوبت

مقدار اولیه `current_player` برابر `1` (X) است؛ X همیشه شروع می‌کند. پس از هر حرکت **که بازی را تمام نکند**، نوبت با `current_player = -current_player` عوض می‌شود. در حرکت پایانی (برد یا مساوی) نوبت عوض نمی‌شود.

## ۳. تحلیل محیط هوشمند

### ۳.۱ مدل PEAS

| مؤلفه | شرح | منبع |
|---|---|---|
| معیار عملکرد (Performance Measure) | افزایش نرخ برد، جلوگیری از باخت، انتخاب حرکت معتبر، کاهش زمان تصمیم‌گیری، کاهش تعداد حالت‌های بررسی‌شده (در صورت بهینه‌سازی) | مشخصات فنی |
| محیط (Environment) | صفحه ۳×۳، بازیکن مقابل، قوانین بازی، وضعیت خانه‌ها | مشخصات فنی |
| عملگرها (Actuators) | قرار دادن نماد در یکی از خانه‌های خالی (در کد: فراخوانی `env.step(action)`) | مشخصات فنی + کد |
| حسگرها (Sensors) | وضعیت صفحه، نوبت بازی، خانه‌های خالی، وضعیت پایان بازی (در کد: `board`، `current_player`، `get_legal_actions()`، `done`، `winner`) | مشخصات فنی + کد |

### ۳.۲ ویژگی‌های محیط

| ویژگی | مقدار | علت انتخاب متناسب با بازی دوز |
|---|---|---|
| قابلیت مشاهده (Fully Observable) | کاملاً قابل مشاهده | کل صفحه برای هر دو بازیکن در هر لحظه آشکار است و اطلاعات پنهان وجود ندارد (کد: آرایه `board` به‌طور کامل در اختیار است). |
| قطعیت (Deterministic) | قطعی | نتیجه هر حرکت کاملاً مشخص است و عنصر تصادفی در قوانین نیست. (تصادفی بودن در شبیه‌سازی فقط به انتخاب بازیکن مربوط است نه پویایی محیط.) |
| ترتیبی (Sequential) | ترتیبی | هر حرکت بر وضعیت و گزینه‌های حرکات بعدی اثر می‌گذارد؛ بازی اپیزودی با تصمیم‌های وابسته است. |
| ایستا (Static) | ایستا | بازی نوبتی است و صفحه تا زمان حرکت بازیکن بعدی تغییر نمی‌کند. |
| گسسته (Discrete) | گسسته | فضای وضعیت و کنش‌ها متناهی است (۹ خانه، هر خانه ۳ وضعیت، حداکثر ۹ کنش). |
| چندعاملی (Multi-Agent) | چندعاملی (رقابتی) | دو بازیکن با اهداف متضاد؛ بازی حاصل‌جمع‌صفر است. |

README سه ویژگی گسسته، قطعی و کاملاً مشاهده‌پذیر را ذکر کرده و مشخصات فنی هر شش ویژگی را؛ این دو منبع با هم متناقض نیستند.

## ۵. مستندات فنی محیط بازی (`TicTacToeEnv`)

### ۵.۱ کد منبع (طبق فایل ارائه‌شده)

```python
import numpy as np

class TicTacToeEnv:
    WIN_LINES = [
        (0, 1, 2), (3, 4, 5), (6, 7, 8),
        (0, 3, 6), (1, 4, 7), (2, 5, 8),
        (0, 4, 8), (2, 4, 6)
    ]

    def init(self):                      # <- در فایل ارائه‌شده به‌صورت «init» آمده است
        self.board = np.zeros(9, dtype=int)
        self.current_player = 1
        self.done = False
        self.winner = None
    ...
```

> **هشدار سازنده:** در متن ارائه‌شده نام متد `init` است نه `__init__`. با این نام، پایتون آن را سازنده نمی‌شناسد و `TicTacToeEnv()` بدون خطا ساخته می‌شود اما صفت‌های `board`، `done` و … تا فراخوانی `reset()` وجود ندارند. با این حال آزمون ۲ نوت‌بوک بلافاصله پس از `TicTacToeEnv()` فراخوانی `env.step(0)` را انجام می‌دهد و خروجی ذخیره‌شده، موفقیت را نشان می‌دهد؛ که با وجود `__init__` واقعی سازگار است. محتمل‌ترین توضیح، حذف زیرخط‌ها هنگام انتقال متن (قالب Markdown) است. این مورد باید در فایل اصلی مخزن **تأیید** شود (همین الگو برای `name == "main"` در اسکریپت دیتاست هم دیده می‌شود، بخش ۷).

### ۵.۲ متغیرها و ثابت‌ها

| نام | نوع | مقدار اولیه | کاربرد |
|---|---|---|---|
| `WIN_LINES` | متغیر کلاس، فهرستی از ۸ تاپل | ثابت | خطوط برد |
| `board` | `numpy.ndarray`، ۹ عنصر، `dtype=int` | همه ۰ | وضعیت صفحه (۱=X، ‏-۱=O، ۰=خالی) |
| `current_player` | `int` | ۱ | بازیکن فعلی |
| `done` | `bool` | `False` | پایان بازی |
| `winner` | `None` / `int` | `None` | نتیجه (۱، ‏-۱، ۰ یا `None`) |

### ۵.۳ توابع

#### `__init__` (در فایل: `init`)

| مورد | شرح |
|---|---|
| هدف | مقداردهی اولیه صفت‌های محیط |
| ورودی / خروجی | بدون ورودی؛ بدون مقدار بازگشتی |
| منطق | همان مقداردهی `reset()` را انجام می‌دهد (بدون بازگرداندن کپی صفحه) |
| خطاهای احتمالی | در صورت نام اشتباه، صفت‌ها تعریف نمی‌شوند (بالا) |
| ارتباط | پیش‌نیاز همه توابع دیگر |

#### `reset()`

| مورد | شرح |
|---|---|
| هدف | بازنشانی کامل بازی |
| ورودی | ندارد |

## ۹. الگوریتم‌های هوش مصنوعی

### ۹.۱ وضعیت پیاده‌سازی

> **Minimax و Alpha-Beta Pruning در هیچ‌یک از کدهای ارائه‌شده پیاده‌سازی نشده‌اند.** مشخصات فنی (بخش ۷) آن‌ها را فقط به‌عنوان گزینه‌های ممکن مطرح کرده و صراحتاً می‌گوید آن سند به‌تنهایی به معنی پیاده‌سازی نیست. فایل `lab1_agent_tictactoe.py` که در ساختار پیشنهادی آمده، ارائه نشده است. **پیاده‌سازی تأیید نشده است.**

### ۹.۲ توضیح علمی (نظری و عمومی؛ مربوط به کد پروژه نیست)

**Minimax:** الگوریتم جست‌وجوی خصمانه برای بازی‌های دونفره حاصل‌جمع‌صفر و کاملاً مشاهده‌پذیر. درخت بازی از وضعیت فعلی تا وضعیت‌های پایانی گسترش می‌یابد. به وضعیت‌های پایانی مقدار مثلاً ‏+۱ (برد عامل)، ‏۰ (مساوی) و ‏-۱ (باخت) داده می‌شود. گره‌های عامل بیشینه‌ساز (MAX) و گره‌های حریف کمینه‌ساز (MIN) هستند و مقدار هر گره از مقادیر فرزندان محاسبه می‌شود. عامل حرکتی را برمی‌گزیند که مقدار فرزند ریشه را بیشینه کند. در دوز، به دلیل کوچکی فضای حالت، جست‌وجوی کامل ممکن است و منجر به بازی بهینه می‌شود.

**Alpha-Beta Pruning:** بهینه‌سازی Minimax که نتیجه را تغییر نمی‌دهد. مقدار α بهترین مقدار تضمین‌شده برای MAX و β بهترین مقدار تضمین‌شده برای MIN در مسیر فعلی است. هرگاه β ≤ α شود، بقیه فرزندان آن گره بر تصمیم نهایی اثر ندارند و هرس می‌شوند. کارایی به ترتیب بررسی حرکات وابسته است (در بهترین حالت تعداد گره‌ها حدوداً به ریشه دوم تقلیل می‌یابد).

شبه‌کد توضیحی (غیرمتعلق به پروژه):

```text
function MINIMAX(state, is_max, alpha, beta):
    if state is terminal: return utility(state)
    if is_max:
        v = -inf
        for a in legal_actions(state):
            v = max(v, MINIMAX(result(state, a), False, alpha, beta))
            alpha = max(alpha, v)
            if beta <= alpha: break
        return v
    else:
        v = +inf
        for a in legal_actions(state):
            v = min(v, MINIMAX(result(state, a), True, alpha, beta))
            beta = min(beta, v)
            if beta <= alpha: break
        return v
```

### ۹.۳ تناسب با محیط پروژه

رابط فعلی محیط (`get_legal_actions`، `step`، `done`، `winner`) برای Minimax کافی است؛ اما چون `step` حالت داخلی را تغییر می‌دهد، جست‌وجو یا باید از کپی محیط استفاده کند یا حرکت را برگرداند (undo) — این قابلیت در کلاس وجود ندارد.
